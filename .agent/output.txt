WHAT THE SYSTEM IS
--------------------------------------------------------------------------------
A Weighted Decision Support System (DSS) that recommends an academic stream
(Science / Humanities / Business) to Nigerian SS2 students using an
AHP-SAW multi-criteria decision engine. Inputs: JSS3/SS1 academic scores,
a 48-item RIASEC vocational interest quiz, and a 20-item BFI personality
questionnaire. Output: a ranked stream recommendation with confidence level,
plain-language guidance, AHP weight transparency, and a JAMB O'Level subject
combination validator against a seeded university-course catalog.

STACK
  Frontend: React 18 + Vite 5 + TailwindCSS + React Router 6 + Recharts + Axios
  Backend:  Express 4 + TypeScript (ESM) + Zod validation
  Database: PostgreSQL + Prisma 7 (adapter-pg, generated TS client)
  Engine:   Pure TS modules (AHP, SAW, RIASEC, BFI, confidence) — no DB/HTTP deps
  Auth:     JWT (7d expiry, bcrypt-12 hashing), role claim on token,
            requireRole guard, pnpm create:admin bootstrap script
  Deploy:   Vercel (static client) + server behind reverse proxy (Railway/Cloudflare)

WHAT'S ALREADY STRONG (keep — these are thesis strengths)
--------------------------------------------------------------------------------
1. Clean engine separation — AHP/SAW/RIASEC/BFI are pure, testable ESM modules
   with zero DB or Express coupling. Exactly what an examiner wants to see.
   (Unit tests still missing — see Gaps.)
2. Auditable recommendation logs — RecommendationLog snapshots inputs, weights,
   and algorithm version as JSON. Closes the explainability gap and is a
   genuine differentiator.
3. Fully normalized subject scores (SubjectScore rows + unique constraint) —
   adding a subject is an INSERT, not a migration.
4. Raw psychometric responses persisted separately (RiasecResponse/BfiResponse)
   — supports re-scoring and the 100-profile validation study from the thesis.
5. Zod validators derive enums directly from Prisma's generated enums — enum
   drift is structurally impossible.
6. Reasonable security posture: helmet, CORS allowlist, rate limiting
   (auth: 20/15min, api: 200/5min), JWT + bcrypt-12, 100kb body limits,
   audit-log table defined.
7. Auth plumbing for RBAC exists end-to-end and is now APPLIED: admin routes
   are the first real consumers of the guard (token claim → guard → bootstrap
   script → live /api/admin/* endpoints).

MAIN GAP — NO ADMIN DASHBOARD / ANALYTICS UI (API done, UI missing)
-------------------------------------------------------------------------------
The schema already models Counselor, School, Admin (role), AuditLog and all the
data needed for oversight. The /api/admin/* API is now live (see Progress), but
the client side is still missing:

  • No admin dashboard, analytics, or data-visualization UI in the client
  • requireRole now guards all /api/admin routes, but every STUDENT route is
    still open to any authenticated role (no /me role gating yet)
  • AuditLog is defined but never written (no code inserts audit records)
  • Counselor/Student assignment exists in the schema but has no API/UI
  • School model is completely unused (register even concatenates schoolName
    into careerAspiration as a workaround — FIX Bug 2.1)
  • lastLoginAt is tracked but never surfaced

This remains the single highest-value build: an Admin Dashboard + analytics
layer gives the thesis a complete stakeholder story (student → counselor →
school admin → platform admin) and a rich results/data chapter.

ARCHITECTURE NOTES / RISKS
--------------------------------------------------------------------------------
  • Single Student table carries role (STUDENT default); COUNSELOR and ADMIN
    log in through the same table today (create:admin seeds ADMIN). The
    separate Counselor entity is unused. Make the login-path decision explicit
    in the thesis.
  • Prisma 7 generated client is committed under server/prisma/generated; the
    post-build scripts/fix-prisma-imports.js step must survive a clean build —
    CI would catch it.
  • The client imports server/enums (server package exports generated Prisma
    enums) — couples the client build to the server workspace. Fine for a
    monorepo; note it in the thesis build pipeline.
  • RecommendationLog grows a row per GET /api/recommend (no dedup) — fine at
    project scale, worth noting for the results chapter.
